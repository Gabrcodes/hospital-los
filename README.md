## Project Overview

This project addresses two complementary prediction tasks on hospital LOS data:

| Task | Target | Primary Metric |
|------|--------|---------------|
| **Regression** | Exact LOS in days (continuous) | RMSE |
| **Classification** | Risk class — Short (0–3 d) / Medium (4–7 d) / Long (≥ 8 d) | Weighted F1 |

An interactive **Streamlit dashboard** (`dashboard.py`) loads the trained artifacts produced by `models.py` to support cohort filtering, per-patient risk inference, and side-by-side model comparison.

### File Dependency

```text
LengthOfStay.csv
      ↓
  models.py          ← source of truth: trains, evaluates, saves everything
      ↓
saved_models/   plots/
      ↓
  dashboard.py       ← reads saved artifacts; never hard-codes results
      ↓
  Streamlit UI
```

> **Always run `python models.py` before launching the dashboard.** The dashboard reads from `saved_models/` — if those files are missing it will show a warning.

| Model | R² | RMSE (days) | MAE (days) |
|-------|----|-------------|-----------|
| Linear Regression | 0.7495 | 1.186 | 0.898 |
| Decision Tree | 0.7941 | 1.075 | 0.825 |
| Random Forest ★ | 0.9122 | 0.702 | 0.491 |
| **XGBoost ★** | **0.9611** | **0.467** | **0.354** |

- Bonus model. XGBoost predicts within ~11 hours of the actual stay duration on average.

### Classification

| Model | Accuracy | F1 (weighted) | Long-stay Recall |
|-------|----------|--------------|-----------------|
| Logistic Regression | 0.803 | 0.798 | 0.514 |
| K-Nearest Neighbours | 0.798 | 0.771 | 0.102 |
| Linear SVM ★ | 0.774 | 0.770 | 0.600 |
| Random Forest ★ | 0.889 | 0.888 | 0.724 |
| **Neural Network ★** | **0.895** | **0.894** | **0.722** |

- Bonus model. Long-stay Recall is the per-class recall on the Long (≥ 8 d) cohort — the most clinically critical metric.

## Usage

### Step 1 — Train models and generate all artifacts

```bash
python models.py
```

This trains all 9 models, evaluates them on the held-out test set, and writes:

```text
saved_models/regression_model.pkl       ← best regression pipeline
saved_models/classification_model.pkl   ← best classification pipeline
saved_models/metrics.json               ← all model scores
saved_models/metadata.json              ← feature columns, class labels, best model names
saved_models/feature_importance.csv     ← full ranked importance table
saved_models/top_features.csv           ← top 25 features
plots/plot_01_*.png … plot_09_*.png     ← all 9 report figures
```

### Step 2 — Launch the dashboard

```bash
streamlit run dashboard.py
```

Open the local URL printed in the terminal (typically `http://localhost:8501`).

## Preprocessing

All preprocessing is **leak-safe**: a `ColumnTransformer` is embedded inside each model's `Pipeline` and fitted exclusively on the training fold.

| Step | Detail |
|------|--------|
| Leakage removal | Drop `eid`, `vdate`, `discharged`, `facid` before splitting |
| Train/test split | 80 / 20, `random_state=42`, `stratify=y_clf` |
| Numeric imputation | Column median |
| Numeric scaling | `StandardScaler` (zero mean, unit variance) |
| Categorical encoding | `OneHotEncoder` with `handle_unknown='ignore'` |
| Classification target | LOS ≤ 3 d → 0 (Short); 4–7 d → 1 (Medium); ≥ 8 d → 2 (Long) |

> Scaling is essential for KNN, SVM, and the MLP. It is harmless for tree-based models. Both are handled transparently by the pipeline.

## Dashboard

The Streamlit dashboard (`dashboard.py`) exposes four tabs:

| Tab | Contents |
|-----|----------|
| **Data Explorer** | KPI cards (patient count, mean/median LOS, long-stay share), LOS histogram, category pie chart — all filtered by sidebar controls |
| **Patient Risk Predictor** | Manual patient-level inputs → predicted LOS in days + risk class + action prompt |
| **Model Comparison** | Regression and classification metrics from `metrics.json` side by side |
| **Feature Importance** | Random Forest importance chart + numeric correlation heatmap |
